# Markdown editor behavior

The editor uses CodeMirror's standard history and key bindings, plus Markdown-aware Enter behavior, syntax coloring, and context-sensitive completions. The reusable behavior lives in `extensions.ts`, `markdownHighlighting.ts`, and `markdownCompletions.ts`, separate from React/DOM lifecycle and autosave handling. Headings use the existing purple brand palette; bold, italic, links, and inline code receive distinct readable colors without hiding Markdown markers. Type `table`, `task`, `image`, `mermaid`, or `chart` and select a completion (or press Ctrl-Space for suggestions); `table` inserts a two-column Markdown table with editable cells, and Mermaid and chart fences also offer their supported keywords. Templates cover tables, checkboxes, standard/wiki images, flowcharts, sequence diagrams, and bar/line chart YAML. This is starter syntax, not full Mermaid/YAML authoring assistance.

- **Markdown formatting:** on macOS use Cmd+B, Cmd+I, Cmd+Shift+X, Cmd+backtick, or Cmd+K; elsewhere use Ctrl+B, Ctrl+I, Ctrl+Shift+X, Ctrl+backtick, or Ctrl+K. These toggle bold (`**`), italic (`*`), strikethrough (`~~`), inline code, or create a link, respectively. With no selection, formatting inserts a marker pair and leaves the cursor inside; the link shortcut inserts a link template with the cursor ready for its URL. Formatting keybindings apply in Vim Insert mode only; Vim Normal and Visual mode retain their own mappings.
- **File Explorer:** `Cmd+S` on macOS or `Ctrl+S` elsewhere toggles the explorer; disable it in Settings to turn off the shortcut.
- **Paste images:** focus a saved note's source editor and use the standard `Cmd+V` (macOS) or `Ctrl+V` (Windows/Linux) with a supported raster image on the clipboard. Storm writes it to the note-adjacent `images/` folder (creating it if needed) and inserts a relative Markdown image link; existing filenames are never overwritten. PNG, JPEG, GIF, WebP, and AVIF up to 10 MB are supported. Text paste and Vim behavior are unchanged; image paste is unavailable in previews, read-only states, and unsaved empty tabs. Unsafe `images/` paths produce an error instead of writing outside the vault. If the note/tab/selection changes while the image is being saved, the file is kept in `images/` but the link is not inserted, avoiding edits in the wrong note.
- **Undo / redo:** `Cmd+Z` / `Cmd+Shift+Z` on macOS; `Ctrl+Z` / `Ctrl+Shift+Z` elsewhere. CodeMirror history is local to the current editor session and is not persisted across reloads.
- **Enter:** continues Markdown list, task-list, and blockquote markup where applicable; Enter twice exits an empty item where CodeMirror supports it. At the end of a Markdown table header, Enter creates a separator and first body row; subsequent table rows are added with Enter. This is source editing only, and in Vim mode applies only in Insert mode. Completion acceptance retains priority.
- **Tab / Shift+Tab:** outside Markdown lists, Tab inserts two spaces; in list items, Tab / Shift+Tab indents or outdents the list. Active completions keep priority, and Vim mode applies these behaviors only in Insert mode.
- **Ctrl+1 / Ctrl+2 / Ctrl+3 (macOS); Alt+1 / Alt+2 / Alt+3 (Windows/Linux):** focus Vaults, File Explorer, or Editor, respectively. These native app shortcuts work regardless of Vim mode; bare digits remain available for Vim count prefixes and normal typing.
- **?:** opens Keyboard shortcuts from navigation panes, from an empty tab, or from Vim normal mode. It is ignored while typing in a note, name, search, or command/dialog. In Vim normal mode this takes precedence over Vim's default backward-search `?`.
- **Vim editor motions:** in Vim Normal and Visual modes, `Shift+J` (`J`) moves to the next paragraph (same motion as `}`), and `Shift+K` (`K`) moves to the previous paragraph (same as `{`). They also work as operator-pending motions (for example, `dJ`). In Insert mode and with Vim disabled, uppercase `J` and `K` are not intercepted.
- **Vim navigation:** in the Vaults pane, `j` / `k` moves between vaults; `l` activates the focused vault while keeping focus in Vaults, and Enter activates it and moves focus to the File Explorer. In the File Explorer, `j` / `k` moves through visible entries, `h` / `l` closes or opens folders, and `l` opens Markdown notes while keeping focus in the Explorer; Enter opens a note and focuses the Editor (including an already-open note). Failed or cancelled navigation does not intentionally move focus.
- **Line numbers:** the editor gutter displays line numbers with a transparent background and muted text, so it does not add a contrasting strip or border.
- **Long lines:** wrap in the editor rather than requiring horizontal scrolling.

Each open note has its own in-memory CodeMirror `EditorState`, preserving document, selection, scroll position, and undo history while switching readable tabs. Empty tabs have a stable session-only ID and no note path; they show the centered `storm` placeholder with `cmd + p` to search notes and `cmd + shift + t` to restore last tabs; these hints never read or save a file. Use `Cmd+T` on macOS or `Ctrl+T` elsewhere to create one (also available via the plus button). Switching to an empty tab clears the preview's note identity and content; opening another note derives both from that note's editor state. Opening a note while an empty tab is active replaces that tab. Closing an empty tab follows normal neighbor selection, and empty tabs are retained in per-vault session snapshots. Tabs, named tab groups, tab-to-group assignments, collapsed state, and editor view metadata (selection and scroll position) are checkpointed to the vault registry for touched vaults after a 1-second quiet period following layout, selection, or scrolling changes. Checkpoints are best-effort during normal operation; graceful shutdown flushes and saves the latest layout. The app does not auto-open saved tabs at startup; use the Restore Saved Tabs command (`Cmd+Shift+T` on macOS, `Ctrl+Shift+T` elsewhere) to restore the current vault. Note contents and undo history are never stored in the layout; note text remains in the note files and is flushed on graceful shutdown. Tab groups are local to each vault session, and removing a group only ungroups its tabs. The separate Vault Sidebar groups are stored in the vault registry on disk. The active note keeps the existing debounced autosave and flush-before-switch behavior; inactive notes are not independently autosaved. Vim mode is reconfigured on each restored state. Line numbering is included in the shared extension configuration for new notes, empty states, and restored tabs created after the updated renderer loads; in-memory tab states held by an already-running renderer need to be recreated/reloaded to receive the new extension.

## Numbered navigation shortcuts

Right-click a tab to create a tab group, move the tab into a group, or ungroup it; right-click a group header to change its color, rename, or remove it. Drag tabs and group headers to reorder them. The same actions are available from the focused tab or group header with the Context Menu key or Shift+F10. Drag tabs within or between groups, onto a group header to assign them, or into the ungrouped section; drag group headers to reorder groups. Drop positions are chosen by the target's midpoint. Dragging is limited to the current vault window/session; tab order, group membership, group colors, and collapsed state are checkpointed for touched vaults. These use the shared renderer context menu; the new-tab plus button remains visible. Use `⌘T` on macOS or `Ctrl+T` elsewhere to open a new empty tab. Fully restart the app after changing the native menu accelerator. Use `⌘1`–`⌘9` on macOS or `Ctrl+1`–`Ctrl+9` elsewhere to select the open tab at that displayed position. Focus Vaults, File Explorer, or Editor with `Ctrl+1`–`Ctrl+3` on macOS or `Alt+1`–`Alt+3` elsewhere. Use `Ctrl+Shift+1`–`Ctrl+Shift+9` on all platforms to activate the registered vault at that position. Positions follow the visible tab order and registered-vault list order; unavailable positions do nothing. Tab selection uses the normal flush-before-switch flow, and vault activation preserves the existing session snapshot and validation behavior. Restart the app fully after changes to native menu accelerators.

## Window layout

The renderer reserves a 36px draggable titlebar strip above both panes for the macOS traffic lights. The explorer and editor share the remaining row height and use matching 16px insets; their height follows the flex layout rather than separate viewport calculations. The editor card has zero inner padding, and the tab strip remains a separate, square-edged row above it. CodeMirror content has 16px horizontal padding and zero vertical padding. Save status overlays the bottom-right corner of the CodeMirror pane (not the preview) without reserving vertical space. App-operation failures appear as dismissible bottom-right toasts; transient notices dismiss after seven seconds, while save failures remain until dismissed.

## Live Markdown preview

The editor card is split into two independently scrolling panes: CodeMirror on the left and a live rendered preview on the right. The preview is derived directly from the active CodeMirror document on edits and explicitly refreshed whenever a tab state is installed or the editor is cleared. It has no editable or persisted state; autosave and tab snapshots continue to use the CodeMirror document as the sole source of truth. Both panes remain constrained to the existing editor card.

Rendering uses `react-markdown`; raw HTML is not rendered. Wiki note links `[[note]]`, `[[folder/note]]`, and `[[note|label]]` open a uniquely resolved note in the current vault. Relative-to-current-note matches take precedence, followed by vault-root matches; bare filenames must resolve uniquely. Missing or ambiguous links report an error. Heading fragments and block links are not supported. Inline `$x^2$` and display `$$\\int_0^1 x\\,dx$$` math use locally bundled KaTeX (escape a literal dollar as `\\$`). KaTeX runs with trust disabled, bounded expansion/size, local warning/error rendering, and no external asset loading; unsupported commands and HTML extensions such as `\\href`/`\\includegraphics` are not enabled. KaTeX's own CSS/fonts are bundled locally. Display equations scroll horizontally within the preview. Fenced `mermaid` diagrams use the bundled Mermaid renderer with strict security and sanitized SVG. Fenced `chart` blocks use the Obsidian Charts YAML subset: `type` (`bar`, `line`, `pie`, `doughnut`), `labels`, and numeric `series` entries. Invalid blocks show a local error rather than interrupting the preview.

Standard Markdown images and `![[image.png]]` wiki embeds load only raster files from the note's vault through the vault-image IPC API. Wiki embeds support `|alt text` or a numeric `|width`. Remote/protocol URLs, SVG, and other unsupported formats are not rendered; bare wiki filenames must resolve unambiguously. Each preview request receives the vault ID and note path from the active tab snapshot, not a mutable global vault selection. The preview also renders stable GFM task lists, tables, and strikethrough. Task checkboxes are accessible and clickable: a click updates only the source checkbox marker in the current CodeMirror document, so ordinary undo and debounced autosave apply. A stale preview or changed tab is ignored rather than writing to a different note. Tables scroll within the preview pane. This remains a focused Markdown subset, not full Obsidian plugin parity; raw HTML is not enabled.

After changing the main/preload asset API, fully restart the app. The repository has no dedicated renderer test script; run the available typecheck, lint, and build checks, plus the vault asset tests.
